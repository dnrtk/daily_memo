1. 概要

作業フォルダ自体を Git リポジトリにし、GitHub・GitLab・任意の Git サーバー・ファイルサーバ上の bare リポジトリのいずれかと同期します。 保存すると自動でコミットされ、編集が止まったタイミングや一定間隔で送受信します。手動同期(Ctrl+Shift+S)とメモ付きの同期もできます。 同じ箇所を複数の端末で編集した場合は、専用画面で箇所ごとにどちらを残すかを選べます。

2. 主な判断

論点採用理由・却下した案
Git の実装システムの git CLI を呼ぶHTTPS は Git Credential Manager、SSH は ssh-agent と、普段の git の認証設定がそのまま使える。libgit2(git2)は SSH・認証まわりが弱く、gix は push が未成熟なので見送り
コードの配置新クレート memo-sync既存の「ロジックは UI 非依存のクレート、Tauri 層は薄く」の方針に合わせた。実際の git を使った結合テストを書きやすい
取り込み方式merge(rebase ではない)rebase は競合が複数コミットにまたがると解消が何度も必要になる。メモ用途では履歴の直線性より分かりやすさを優先
端末ごとの情報.git/config(有効化・最終同期時刻)とアプリ設定(間隔・端末名)作業フォルダ内の共有ファイルに置くと、それ自体が同期されて端末間で衝突する
同期しないもの.memo/*(categories.yaml を除く)、一時ファイル、Office のロックファイル検索インデックスは端末ごとに作り直せるうえサイズが大きい。カテゴリ定義は共有したいので同期する
改行コード.gitattributes に * -text、git 呼び出しで core.autocrlf=falseこのアプリは CRLF・Shift_JIS を元の形式のまま保存する設計。git の変換が入ると Windows / Linux 間で差分が出続ける
上位フォルダが Git 管理下作業フォルダを独立したリポジトリにするホームフォルダを dotfiles 用に Git 管理していると、その配下が全部「入れ子」扱いになる(この PC がまさにそうだった)。拒否するより独立させる方が実用的
ファイルサーバの所有者そのリモートに限り safe.directory=*共有フォルダ上のリポジトリは所有者が別ユーザーになりやすく、git 2.35.2 以降は拒否される。作業フォルダ側はそのパスだけを許可
コミットの端末名コミットに Device: トレーラーを付けるuser.name は全端末で同じことが多く、どの端末の変更か区別できないため。user.name / email が未設定でも端末名から補ってコミットできる

3. 同期の流れ

初回接続

まずリモートに接続できるかを確認し、失敗したら作業フォルダには何も変更しません。リモートが空ならこの端末の内容を送ります。データがあれば取り込んで合わせ、同じパスで内容が違うファイルはこの端末の版を別名で残してからリモートの版にします(どちらも消えません)。categories.yaml・.gitignore・.gitattributes はリモート側を優先します。

4. 競合の扱い

状況扱い
テキストを両方で編集し、重なっていないgit が自動で統合する(画面には出ない)
テキストの同じ箇所を両方で編集解消画面で箇所ごとに「この端末 / 相手 / 両方(順序 2 通り)」を選ぶ。結果を直接編集してもよい。「両方のファイルとして残す」も選べる
Office・PDF・画像を両方で変更自動で両方残す(相手の版を 名前 (競合 端末名 日時).拡張子 で保存)
一方が編集、他方が削除(テキスト)解消画面で「残す / 削除」を選ぶ
一方が編集、他方が削除(バイナリ)編集された側を自動で残す(データを失わない方向)

競合中も作業ツリーには常に「この端末の版」が置かれます。<<<<<<< などのマーカーがエディタや検索インデックスに入り込まず、解消を後回しにしても編集を続けられます。差分の計算は git merge-file にマーカー長 32 を指定して行い、Markdown の見出し下線(=======)と取り違えないようにしています。

5. UI / UX

  • ステータスバー: 同期済み / 未送信 N / 同期中 / オフライン / 認証エラー / 競合 N をアイコンと文字で表示します(色だけに頼らない)。完了時にアイコンが小さく弾み、競合時は 2 回だけ揺れます。
  • パネル(ステータスバーをクリック): 状態、接続先、未送信の変更(A/M/D)、メモ付きの「今すぐ同期」、最近の更新(端末名・相対時刻)、自動同期の設定内容を表示します。
  • 設定 → 同期: 未設定のときは「① 種類のカード → ② URL / パス入力と確認 → ③ 端末名」の順に進みます。確認結果に応じて開始ボタンの文言が「アップロードして / 取り込んで / 作成して 同期を開始」に変わり、何が起きるかを事前に説明します。入力内容から種類を自動で推定します。
  • エラー: 原因を分類(ネットワーク / 認証 / 見つからない / 所有者 / 拒否)して日本語で表示します。git の出力は「詳細」に折りたたみます。自動同期の失敗はトーストを出さず、状態表示だけを変えます。
  • 軽さ: git の処理はすべて Rust 側の別スレッドで動かし、同時に 1 つしか実行しません。状態取得は git status --porcelain=v2 の 1 回で済ませます。保存のたびではなく、編集が止まってからまとめて送ります。アニメーションは transform / opacity のみで、prefers-reduced-motion のときは止めます。

6. 検証

  • cargo test -p memo-sync: 単体テスト 10 件と、実際の git で「ファイルサーバ上のリモート + 2 端末」を作る結合テスト 8 件(接続・自動統合・箇所ごとの解消・両方残す・バイナリの自動解決・削除と編集の競合・CRLF の保持・オフライン後の再送)がすべて成功
  • cargo clippy --workspace --all-targets: 警告なし。tsc --noEmit と vite build も成功
  • 画面: Tauri の呼び出しをモックしたプレビューをブラウザで開き、パネル・設定の初回フロー・競合画面の表示と操作を確認(確認後にモックは削除)
  • 未検証: Tauri アプリとしての実起動、GitHub / GitLab への実際の HTTPS・SSH 認証、UNC パスの実ファイルサーバ、Linux 実機

7. 確認してほしい点

既定値は「自動同期オン・5 分ごと・保存の 1 分後・起動時と終了時も同期」にしました。通信量や GitHub へのアクセス頻度が気になる場合は、設定 → 同期で変更できます。

初回接続でリモートにデータがあるときは、カテゴリ設定(categories.yaml)をリモート側に合わせます。この端末でカテゴリを独自に変更していた場合、その設定は失われます(フォルダとファイルは残ります)。

コミット時に git のフック(pre-commit 等)は実行しない(--no-verify)ようにしています。メモ用リポジトリでフックを使う予定があれば変更が必要です。
